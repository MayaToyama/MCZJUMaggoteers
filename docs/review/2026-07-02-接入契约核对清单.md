## G. 🟡 第三轮新发现（不阻塞 plan，但 plan/实现须覆盖）

### G1. MGC **房间 JSON 实例**是 join 前置条件（文档未写清）

- `registerGame` 只注册类；`loadGameRoom` 从 `plugins/MCZJUGameCore/rooms/maggoteers/*.json` 加载**房间实例**。
- `/mgc join maggoteers` → `createGame(gameId)` → `getRandomLeisureGameRoom`；**无 READY 房间则返回 null**，提示「没有空闲的房间」（`DefaultGameManager.java:164-167`）。
- `MaggoteersRoom extends JsonGameRoom` 可以零字段，但**运维须至少创建一个房间**（如 `/mgcop room create maggoteers default`），或插件 `onEnable` 释放默认 `rooms/maggoteers/default.json`。
- 测试服现有 `rooms/VampireSurvivor/test1.json`，**尚无 `maggoteers/` 目录**——首测前必做。
- 对局结束 MGC 将 room 置回 `READY`（`solveGameEnd`），可复用同一占位 room；**每局仍自建虚空世界**，room 只是 MGC 调度壳。

**建议写入 plan 阶段 0**：部署清单 + 可选 `onEnable` 自动创建默认 room。

### G2. `PlayerExt.giveItem(id)` ≠ ItemCreator（§2.4 易误导）

- 1.0.5 `PlayerExt.giveItem(String id)` 走 **`MCZJUGameCore.getItemManager()`**（MGC 内置物品），**不是** ItemCreator。
- 本插件货币/复活币/武器由 **ItemCreator + `ItemService`** 生成（§3、§8、clearReward）。
- **实现规则**：波次 `clearReward`、3 选 1 发补给/武器 → `ItemService.createItem(id)` + `player.giveItem(ItemStack)`（或 inventory.addItem）；**不要**对 ItemCreator id 调用 `giveItem(String id)`，除非另行注册进 MGC ItemManager（不推荐）。

**建议**：plan 中 `CurrencyService` / `RewardService` 明确走 `ItemService`；§2.4 可在实现时加注释「giveItem(id) 仅当 id 已在 MGC ItemManager 注册时可用」。

### G3. `waves.yml` 示例 `point: boss` 要求 `points.yml` 有对应编号

- §7.4 `b_iron_golem_guard` 用 `point: boss`，但 §5.2 `points.yml` 示例只有 `1`、`9`，**缺 `boss` 条目**。
- 实现期配置校验应报错；每张地图 `points.yml` 须定义 Boss 刷怪点（或改 strategy 用数字编号）。

**建议**：默认样例地图 `points.yml` 补 `boss:` 坐标；RunPlanner 解析时校验 point id 存在。

### G4. 建世界触发责任未点名（小歧义）

- §2.3：`onGameInit` = 异步 RunPlanner + 预读 NBT；§4.1：`onGameStart` 流程含「回主线程 createWorld」。
- 未明确**谁**在主线程调度 `createWorld()`（init 里 `runTask` 一次 vs start 门闩内触发）。
- 两种写法均可，但 plan 应定一种，避免 init/start 双触发或遗漏。

**建议默认**：`onGameStart` 门闩内——主线程 `createWorld()` + 粘贴 Act1；`onGameInit` 仅异步 RunPlanner + NBT 预读。
