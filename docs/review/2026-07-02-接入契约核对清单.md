## A. 🔴 Blocker — 元进度系统依赖的 MGC 持久化 API **不存在**

> 账户货币 / 解锁 / 商店 / 排行榜（`CLAUDE.md` §13、§2.2、§2.4、§8、§11、§13.5）全部建立在 `JsonPlayerData` + `getPlayerDataManager().registerPlayerData()` + `PlayerExt.getData()` + `PlayerDataLeaderboard` 之上。**这些在本版 MGC 中全部不存在。**

**证据**：
- `MCZJUGameCore.java`（主类）暴露的 manager 里**没有** `getPlayerDataManager()`。实际只有：`getPlayerManager / getGameManager / getPartymanager / getGameRoomManager / getMenuFacade / getItemManager / getConfigManager / getProfileManager / getProfileCapture / getProfileStorageManager`。
- 全仓库**无** `JsonPlayerData`、`PlayerDataLeaderboard`、`registerPlayerData`、`PlayerExt.getData(...)`、`PlayerExt.resetState()` 的定义。
- MGC 真实持久化 = **profile 系统**：`ProfileData` 存 `Map<profileId, PlayerSnapshot>`，而 `PlayerSnapshot` 仅含 `mainContents / armorContents / offhand / enderChest / xpLevel / xpProgress`（`profile/PlayerSnapshot.java`）。**只能存原版背包/末影箱/经验，不能存 balance/totalEarned/unlocks，也无排行榜 API。**
- 自动保存周期是 **30 分钟**（`MCZJUGameCore.java` `startAutoSave(20*60*30L)`），非文档所写"5 分钟"，且保存的是 profile 快照不是自定义数据。

## B. 🟠 已确认的 API 用法错误（不改会编译不过 / 行为不符）

- [ ] **B1. `MenuFacade.registerMenu` 签名错误**（`CLAUDE.md` §2.2、§13.3）
  - 文档写：`registerMenu("maggoteers_shop", ShopMenu.class)`（字符串 id + 类）。
  - 真实签名：`registerMenu(Class 菜单类, String 标题, int 行数(1~6), String 权限节点)`；菜单靠 `new ShopMenu(player).open()` 打开、按 **Class** 索引，**不存在"字符串 id 菜单"**（`menu/MenuFacade.java`、`guide.md`）。
  - 正确示例：`MenuFacade.registerMenu(ShopMenu.class, "<gold>商店", 6, "maggoteers.shop");`
  - `Menu` 子类构造固定写法：`public ShopMenu(Player p){ super(ShopMenu.class, p); }`，重写 `setup()` 用 `setSlot(...)`。

- [ ] **B2. `PlayerExt.getData(...)` 与 `resetState()` 不存在**（§2.4）——删除这两处引用，改用最终持久化方案的取数方式。

- [ ] **B3. "异步建世界"错误**（§2.3、§4.1）
  - 文档写 `WorldService.createAsync（建世界）` 放 `onGameInit` 异步跑。
  - `WorldCreator.createWorld()` **必须在主线程**；前代 VampireSurvivor 也是**主线程同步建世界、仅删目录异步**（`MCZJUvampireSurvivor/.../WorldManager.java` `createWorldForGame` 同步 `createWorld()`；`runTaskAsynchronously` 只用于 `deleteDirectory`）。
  - 改为："异步准备（读 NBT / 算 RunPlan）→ 回主线程 `createWorld()` + 结构粘贴"。

- [ ] **B4. `onGameStart()` 返回 `void`、不能阻塞等待**（§2.3）
  - 源码 `AbstractGame.gameStart()` 调完 `onGameStart()` 立即置状态 `RUNNING`。
  - 若世界/剧本异步生成，`onGameStart` 无法阻塞等待就绪。需用 `runTaskTimer` **轮询就绪** → 就绪后再传送玩家 / 启动 `WaveScheduler`。在文档中写明这个"就绪门闩"。

- [ ] **B5. jitpack groupId 存疑**（§1.3）
  - pom 用 `com.github.mczju-ops`，但源码包名是 `com.github.mczjuops`（无连字符）。
  - jitpack groupId = `com.github.<GitHub组织名>`；按**实际 GitHub 组织名**核实，否则拉不到依赖。

## D. 🟡 设计层待定项（不阻塞编译，但进 plan 前宜定规则）

- [ ] **D1. 净化"0 秒 255 级凋零抵消"存疑**（§10.2）：该技巧机制不成立的可能性大，免疫凋零/中毒更可能要靠监听 `EntityDamageEvent` 按 `DamageCause` cancel。实现期实测，若不成立则改方案。
- [ ] **D2. 道具 CD 用 `setCooldown` 的材质冲突**（§10.3）：`HumanEntity.setCooldown(Material,ticks)` 粒度是**材质**，同材质的不同 PDC 武器会串 CD。默认改走**时间戳表**（按 PDC id），文档写明。
- [ ] **D3. 3 选 1 可选项 < 3 的 fallback**（§9.1、§12.2）：unique 选光 / 解锁项少时不足 3 个，需定规则（补低价项？允许重复？灰显空位？）。
- [ ] **D4. `onGameEnd` 区分胜/负**（§13.2）：胜利与失败都走 `endGame`→`onGameEnd`，但结算不同。需在游戏状态里存显式 `outcome`(WIN/FAIL) 标志。
- [ ] **D5. `ADD_ATTRIBUTE` 多层叠加需唯一 `NamespacedKey`**（§12）：1.21 的 `AttributeModifier` 用 `NamespacedKey` 标识，同 key 重复添加会抛异常；`stack: ADD` 每层要生成唯一 key。
- [ ] **D6. `mob_count` "概率补 1" 必须走种子 RNG**（§7.6）：否则破坏 RunPlan 的确定性/可重放。
- [ ] **D7. 触发型被动（如 lifesteal）缺 `stack` 语义**（§12）：重复获得是叠加两次还是忽略，需定义。
- [ ] **D8.（可接受，仅记录）** 结构粘贴主线程瞬时掉帧；人数中途减少时 `scalingSnapshot` 仍按开局人数（偏难）。文档已接受，建议在 §18 风险中登记。
